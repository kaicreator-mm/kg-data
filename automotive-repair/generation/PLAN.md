- **当前唯一阶段**：知识生成
- **当前唯一内容格式**：Markdown `.md`

- **知识状态**：默认 `MODEL_GENERATED_UNVERIFIED`；不含正式 N3 / OEM / 认证结论。

## 1. 正确目标

目标不是填满固定知识类型和领域×单元矩阵，而是：

> 逐步形成足以解释汽车结构、工作机理、故障发生、症状差异、诊断依据与维修决策边界的**关联知识网络**；每个生成任务围绕明确的专业问题与必要的依赖知识开展，生成有深度的原创解释，并推动下一轮问题发现。

计划是**知识问题 DAG**，不是书籍目录的机械转录，也不是知识分类树。一本书的章节、真实维修问题、研究主题都可以产生候选任务，但必须明确“该任务究竟要回答什么”。

**原则**：
1. 先计划，后生成；计划粒度控制在可执行的下一个工作批次，不一次性写几百条泛化任务。
2. 前置关系只用在真实知识理解有先决条件时；能并行的主题并行。
3. 一项任务足够深入才完成；没有“每个类型/单元至少 N 条”的配额。
4. 生成正文时允许根据具体问题自由设置小节，不使用强制八知识类型模版。
5. 从生成中识别新的未知与依赖，更新未启动节点的 DAG；允许拆分/合并/新增任务。
6. 当前不生成 LinkML/YAML/JSON-LD/CSV，不进行独立专业事实核验、知识融合或下游应用实施。

## 4. 单个知识任务的内容约定（非固定知识类型）

每个 `AT-xx.md` 必须由**当前具体知识问题**组织自然章节，而不是模板填空。可以根据问题需要包含：
- 要解释的现象/问题；概念和物理或逻辑机制；必要的公式与适用条件；系统或对象间的关系；
- 真实有帮助的条件差异、反例、多个竞争性解释；常见误区；连接其它知识的链接；
- 尚未查明的参数、OEM/版次适用边界、知识缺口与后续具体任务。

**不要因为没有某一种预设知识类型而制造该类型段落**；但对机理/因果关系/适用条件等已知重要的内容，不应仅为缩短篇幅而略过。

文件开头至少说明 `Task ID`、知识问题、可见输入（TOC_ONLY/BOOK_BODY/EXTERNAL/MODEL 或其组合）、生成范围和 `MODEL_GENERATED_UNVERIFIED`；这些是来源与执行范围元数据，不是知识类型分类。

## 5. 生成阶段的实际验收

- `PLAN_READY`：问题具体、依赖无环、输出路径不冲突、有可操作完成条件、真实材料的可见性界定清楚；由**其他对话**独立检查计划质量（不构成专业知识事实核验）。
- `GENERATED`：Markdown 文件实际写入 `kg-data` 并回读；完成该问题所需的专业说明，非空洞概述、非重复堆砌；记录有因果价值的新疑问，并更新可用 DAG；保留生成模型及任务身份收据。
- `DEFERRED`：缺乏足够信息时保留 UNKNOWN 和缺口，不能编造厂商标准、限值或维修安全步骤。
- `NOT_IN_SCOPE`：暂不做独立专业来源认证、LinkML/结构化转换、跨书知识融合或正式合格知识晋升。
- 测量重点：有意义的问题链覆盖、解释深度、跨节点知识依赖、独有知识增量、错误和未知披露、生成成本、返工比例；不可把文件数、字数、Task 数、固定格子完成率作为主质量指标。
