# 跨系统汽车诊断方法：证据分层、竞争假说、误修与 UNKNOWN（DISC-METHOD）

> Task: `DISC-METHOD` · MAIN: [parts-system #61](https://github.com/kaicreator-mm/parts-system/issues/61) · 仅第一阶段原生 Markdown 知识生成，`MODEL_GENERATED_UNVERIFIED`，**非 OEM/VIN 专业诊断资格**。本文讨论信息和因果的分析方法，**不执行维修操作、现场测量、路试、车载 ECU 编程、制动或高压作业**，也不把任何 DTC 直接映射成需要更换的零件。相关例子只是条件化研究假说，车辆适用性及真实故障频率为 `UNKNOWN`。

## 1. 诊断问题应该如何表述：观察、状态、机理与根因

先把维修叙述拆成不同的对象，禁止从“警告灯亮”跳跃到“换零件”：

| 层级 | 研究对象 | 示例（非特定车型结论） | 不能直接推出 |
|---|---|---|---|
| `S0` 主诉与现象 | 驾驶员描述、发生工况、时间顺序、温度/负载/速度 | 冷机后抖动、热车换挡冲击、制动报警 | 任一部件已损坏 |
| `S1` ECU/仪表事件 | MIL、DTC、冻结帧、可见状态位、监测就绪 | OBD 发动机报码、ABS 控制系统报告轮速相关异常 | 该 DTC 就是实际根因或唯一故障 |
| `S2` 可信物理证据 | 特定测点/条件下的电压、电流、温度、机械压力、流量等 | ECU 请求压力与独立物理测点压力不一致 | 一次读数即可证明最终根因 |
| `S3` 因果机制候选 | 失效如何改变流动、扭矩、信号、热量或控制反馈 | 局部油路堵塞、传感偏置、轮胎附着不足 | 此候选在目标 VIN 必然成立 |
| `S4` 归因与决策 | 竞争假说的证据权重、反例、维修误判成本和下一信息价值 | 同一症状保留机械/液压/电气/控制解释 | 直接可执行维修、检修或更换授权 |

理想研究问题格式是：“**在某一明确适用的车辆架构和工况下，哪些候选原因能够通过什么物理机制导致所见现象，哪些可靠观察最能区分它们？**”而不是“报码 Pxxxx 需要换什么零件”。这个格式适用于发动机、传动、制动、电气及 HVAC，不强迫所有分支采用相同传感器或流程。

## 2. 三类图绝不能混淆：结构、知识因果、执行 DAG

- **汽车结构图**：车辆 → 系统 → 子系统 → 总成 → 部件。可有跨系统共享接口；节点所属位置依动力架构、年份和设计变化。
- **机制/因果网络**：部件、控制反馈、热/流量/机械状态、故障、现象与证据的多对多联系。可能有反馈环，如 ECU 扭矩管理 ↔ 发动机反馈、轮胎附着 ↔ ABS/ESC 控制；**不能因为有环就误当知识错误**。
- **知识生成 Task DAG**：为产生有用 Markdown 所必需的真正知识前置；仅这一层必须无环、写集独立。制动知识不应为等待发动机所有故障完结而停工。

本篇为通用方法，不覆盖 [结构](../transmission/automatic/structure.md)、[功能](../transmission/automatic/power-path.md) 或具体 [AT 误修鉴别](../transmission/automatic/diagnostic-repair.md) 的专题正文。专业内容只引用现存唯一知识，减少重复。

## 3. DTC、MIL、冻结帧、监测就绪分别告诉我们什么

### 3.1 OBD 是设计为监控与记录的系统，不是全车根因预言机

- DTC 提供监测系统识别的某一异常条件或控制层异常类别；相同的报码可能由传感器、供电/接地、机械状态、控制目标偏差等不同路径触发，也可能有级联报码。
- 故障相关码可分当前/历史/待确认等形式，但不同车、诊断协议与工具展示会不同；不能无条件认为所有状态相同。
- **冻结帧**是控制器捕获的部分事件工况快照，可能包含相关温度/负载/转速、传感量，记录机制和可用字段依协议与车型变化。它不是完整连续实验曲线，也不是物理真值的认证。
- **MIL** 是仪表提示与 ECU 指令/电路行为的结果；读取工具的“灯命令”与实际灯/显示及历史状态可能不一致。
- **Readiness/监测就绪**说明某监测检查是否已经运行并满足其就绪条件，**不是“车辆无任何故障”的总证明**。监测没有运行与监测检测到故障是不同状态；无故障码也不证明所有系统均已验证。

US EPA 的原始 OBD 资料分别讨论了 MIL、DTC、DLC 与 readiness 的功能关系，并指出监测条件与完成状态的区别。其美国排放检查用途**不等于缅甸对某车型的法规要求**：
- [EPA: On-Board Diagnostic Regulations Q&A](https://nepis.epa.gov/Exe/ZyPURL.cgi?Dockey=P100LW9G.TXT)
- [EPA: Performing OBD checks in inspection programs](https://nepis.epa.gov/Exe/ZyPURL.cgi?Dockey=P1002KRN.TXT)
- [EPA: Evaluation of OBD for identifying fuel vapor losses](https://nepis.epa.gov/Exe/ZyPURL.cgi?Dockey=P100KPTW.txt)

### 3.2 “有码/无码”都必须保留反例

| 观察 | 至少两个候选解释 | 合理的反证思路（知识层面，非实际操作） |
|---|---|---|
| MIL 亮 + 排放相关 DTC | 被监控对象真实异常；传感/供电/线束或另一上游过程导致监测越界 | 对应工况下监控条件、物理量与电控信号是否能够相互解释 |
| 无码 + 明显机械噪声 | 相关对象未被直接监控或未满足报码条件；机械/路面/悬置等来源 | 噪声与载荷、温度、转速及结构位置的关联，非简单“无码=正常” |
| 多个同时出现的 DTC | 共用电源/通信/基准信号扰动；几个独立故障；一个根因引起多个派生码 | 错误时间关系、共用电气源、各事件的因果前置 |
| Readiness 未完成 | 监测条件未满足或状态被重置；实际系统故障也可能存在 | “未运行”和“运行失败”不能直接等同 |
| 机油压力传感读数正常 | 对应测点/信号正常；其他局部油道缺流仍存在 | 不能据一个测点推断所有轴承或涡轮支路真实状态 |
| AT 控制器显示主压力指令 | 控制目标数值；可能有/没有实际压力传感器 | 不能把 ECU 命令当作机械表压，见 [AT 诊断/维修研究](../transmission/automatic/diagnostic-repair.md) |

## 4. 测量学：有效证据必须有对象、工况、量纲和不确定性

研究中的一个“读数”至少说明 `measurand`（究竟测什么）、`instrument_or_signal`（来自哪里）、`position`（测点）、`operating_condition`（温度/速度/负载/状态）、`unit`、`time`、`calibration_version`（若可见）、`scope` 和 `uncertainty`（若未知，明说）。

| 失真源 | 为什么可能误判 | 不能默认做的事 |
|---|---|---|
| 测点位置不同 | 主油道、阀体支路、轮速传感器、线束末端测量的是不同物理状态 | 把两个不同位置的值当“同一压力” |
| 请求值与实测值混同 | ECU 输出有目标/估算/执行器驱动，未必配置独立实际传感 | 把请求为 100% 当真实执行为 100% |
| 时间不同步 | 不同控制器采样、网络传输和 scan-tool刷新周期可产生相位差 | 两条曲线相近便宣称精确因果方向 |
| 传感器偏置/噪声/开路 | 可在真实系统正常时报告异常，也可能掩盖物理异常 | 一个传感信号即排除全部机械故障 |
| 工况差异 | 冷/热、制动/驱动、开环/闭环会改变正常参考值 | 从另一年款或不同工况照搬阈值 |
| 数据缺失 | PID 不受支持、未记录该变量、OEM 私有字段不可见 | 把缺失/空值写成“0”、或用推测冒充采样 |

Bosch 自身的电路分析工具说明指出需要在 scan-tool 读码之外区分传感、线束和 PCM 等故障来源；这可以支持“**码不等于硬件故障确诊**”，却不是证明其某款工具适配缅甸所有车辆：[Bosch VET 100 circuit analysis tool](https://www.boschdiagnostics.com/products/vet-100-circuit-analysis-tool)。

## 5. 竞争假说的筛选：先问信息价值，再考虑备件成本

定义同一症状下的假说集合 `H = {H1, H2, ...}`，每个假说要求：**物理链成立、具体适用性不被排除、有支持/反证、需要额外资料、尚存未知**。

研究表格示例：

| 案例现象 | 竞争根因假说（均非已证实） | 哪类证据更有区分价值 | 没有这些证据时结论 |
|---|---|---|---|
| 低油压/警告 | 油泵供流不足、温度/间隙漏流、局部油道阻力、信号偏差 | ECU 原始信号类型、对应实体压力与工况关系、可信油路结构 | `UNKNOWN`；不能直接换泵 |
| 起步换挡冲击 | 变速箱液压、机械离合/制动器、控制标定、发动机扭矩/悬置 | 准确 AT 类型、请求/实际量、温度、转矩接口 | `UNKNOWN`；传统 AT 机制不适用于 CVT/DCT |
| ABS/制动报警 | 轮速输入/通信、液压执行、轮胎附着、能源/再生系统条件 | 具体制动架构、受监控变量、故障时工况和系统状态 | 最高安全优先，不能从码下结论或建议继续运行 |
| 发动机缺火/动力下降 | 点火/燃油/进气、机械压缩、控制器扭矩限制、传感错误 | 对应架构与事件条件；排除上下游共同来源 | `UNKNOWN`，不把“更换火花塞”当唯一结论 |
| 热管理不达目标 | 冷却液/空气路径、冷媒循环、温度感知、泵/阀控制、环境负荷 | 回路类型及各路径期望/实际条件；适用冷媒版本 | `UNKNOWN`，无资格时不提供冷媒/高压实操 |

**逻辑注意**：证据只能在其真实测量能力和适用范围内支持或反驳假说。没有可靠的故障率先验及测试灵敏度/特异度时，不应输出“80% 是传感器”“概率 90% 是变速箱”等伪定量排名。即便拥有统计先验，故障可以共存，独立性假设须核查；不要把多条来自同一传感器的派生码当成独立投票来叠加置信度。

## 6. 误修风险与价值调度：不要以换件次数当进度

诊断价值不仅在于“找到一个解释”，也取决于避免错换、缩小不确定性和安全后果：

- **高安全后果**（制动、转向、轮端/悬架、HV、燃油泄漏/过热）：即使缺少全部精确信息也应明确“仅知识层解释、停止推断、交合格维修人员核实”；不能把“原因不明”变成可继续行驶/可操作许可。
- **高误修代价**：AT 阀体/变速箱总成、混动动力电子、电驱/电池等复杂部件可能有机械、电控与外部负荷共同原因。在没有具体证据时不应直接下更换建议。
- **高信息价值**：与其列出一长串可能坏的零件，更应找出*在已知资料范围内，什么新的可信信息能最大程度区分最有价值的竞争根因*；实际采集方式须由 OEM/具资格人员决定。
- **配置不一致/来源不可信**：若车系名称与发动机/变速器代号不符、不同年款 OEM 文档冲突、维修参数来源为未核实论坛，则 `STOP_MODEL_SPECIFIC_CLAIM`，在研究中只保留普遍物理机制与 `UNKNOWN`。

研究调度可描述为 `Priority = RiskSeverity × DiagnosticValue × EvidenceReadiness × Nonduplication` 的**概念比较框架**；不赋予无依据的数值权重，也不声称它是某组织的真实风险评估模型。风险等级与故障发生率不能互换。

## 7. 版本与适用条件：跨车型复用时必须精确到够用的层级

| 适用性层级 | 能复用的知识 | 不能自动复用 |
|---|---|---|
| L0 物理与工程原理 | 压差与流量、能量/热、机械载荷、轮胎摩擦的条件性机理 | 车型油压阈值、螺栓扭矩、拆装/安全工序 |
| L1 结构家族 | 传统行星 AT 与 CVT/DCT 区别、ABS/ESC 基本反馈 | 某品牌具体阀体/传感器拓扑 |
| L2 总成/平台 | 在明确 OEM/供应商型号及版本下的总成结构候选 | 同名系统跨年份零件通用 |
| L3 车系代际 | 缅甸在用相关 Probox 或 Honda Fit 某代候选配置 | 每台实际进口车具体发动机或变速器 |
| L4 具体配置/VIN | 只有有对应真实 VIN、制造年、底盘/发动机/ECU、原始 OEM 资料才成立的适配 | 不得由 L0–L3 无证据自动晋升 |

原始 SAE J2012 或 ISO 15031-6 类 DTC 定义属于标准化的诊断术语范畴，不等于故障根因、某 OEM 的具体诊断阈值或已验证实车零件适配。不同标准的版本与适用范围应对应原始出版物，未全文核实时标 `REFERENCE_SCOPE_ONLY`。

## 8. 错误来源与反例：知识生成的自我约束

1. **来源权利和事实边界**：厂商公开产品介绍可以证明技术方案存在，却不能证明某个缅甸车辆实际上安装了该方案；目录/营销材料不是 OEM 维修流程。
2. **模型推理与实测分账**：每个研究假说标 `MODEL_SYNTHESIS`，不能伪装成原始试验、现场维修或经独立专业事实认证。
3. **UNKNOWN vs NOT_APPLICABLE**：缺资料是 `UNKNOWN`；只有车辆构型确定不包含相关组件才可 `NOT_APPLICABLE`。例如非 GDI 车型才有理由排除其特定高压燃油轨。
4. **修订传播**：若上游结构/功能资料被独立审核判 REWORK，受影响的失效、诊断主题必须按具体因果或引用关系标 `STALE`，局部修复后再审核；不应无差别重做所有旧研究。
5. **生成/审核/正式资格分账**：实际 Commit 的 `.md` 是 `GENERATED_REVIEW_PENDING`；其它对话质量 ACCEPT 只授予 `ACCEPT_SCOPED_GENERATION_ONLY`，不是车辆 OEM、真实维修、N3、生产发布资格。
6. **测不到/不允许测**：无安全资质、制造商合法资料或实车许可时，应止于概念性证据类型，**不能提供制动放气、高压带电测量、油轨拆卸、冷媒作业或带路试风险的执行步骤**。

## 10. 交付范围与下一批研究缺口

- **本任务实际完成**：通用观察/机制/根因分账、DTC/Readiness 语义、测量不确定性、竞争性证据、误修风险与适用性层级；避免把故障案例分析取代整车结构与正常机理。
- **未完成**：任何品牌具体诊断手册、准确 DTC 触发条件/信号采样、车型压力/扭矩/机械阈值、实车测量或维修动作；它们依 OEM、VIN 与专业人员资格，仍为 `UNKNOWN`。
- **后继候选**：`DISC-METHOD-EVIDENCE-QUALITY`（证据可靠性/仪器量纲与置信度）、`DISC-METHOD-MAINTENANCE`（维护与磨损预测条件）、`DISC-METHOD-FAULT-TREE`（多根因/证据相互依赖）；这些任务**尚未通过新的 DAG 增量审核**，不能以本篇完成自动启动。
- **跨主题复用**：AT、润滑、制动、HV、热管理及未覆盖系统的失效研究可引用本知识，不能让它取代系统自身的 STR/FUN/FAIL/REP。

**终态**：`GENERATED_REVIEW_PENDING`；源页面是公开基础参考、研究综合未经过另一对话独审，OEM/VIN/N3 事实资格仍为 0。
